## 赛道定位（全稿共用，避免写成单题报告）

本作品对应 **赛道二：数据场景 / 方向 1A：科学数据查找、解析与整合**。

考察点不是答对某一道乳腺癌题，而是：系统能否把任意科研问题当作输入，查找、解析、整合多源异构科学数据，输出可分析、可追溯、可复用的结构化结果，并在发现错误或收到反馈后完成修正。

因此报告按 **模型能力** 写，代表案例只是一条可替换输入。

```text
输入：自然语言科研问题（可替换）
  → 千问或确定性规划理解需求、选择工具
  → 调用 GDC / GEO / cBioPortal / ClinicalTrials.gov / CIViC
  → 解析异构表、字段对齐、来源标注
  → 四层质量门与缺口换方法
  → 输出：患者/样本宽表 + 字段字典 + 溯源 + 质量报告 + 任务级诊断指标
```

**人机分工**

| 角色 | 做什么 | 不做什么 |
|---|---|---|
| 研究者 | 提出科研问题；REVIEW/REJECT 时决定是否换题或接受缺口；Gold Set / 正式 SDTI | 不手工跨库贴患者 |
| 千问 Agent | 解析问题、选择工具、观察后再规划、基于已验证统计写摘要 | 不编造队列、不改质量门、不生成无来源字段 |
| 确定性规则与 Adapter | 调公开库、标准化、身份对齐、医学安全、发布准入 | 不把 IHC 2+ 自动判阳；不把 CNA 当成 IHC；不跨库并患者 |
| 评测模块 | 计算任务级诊断指标、消融表、来源审计；Gold Set 空则阻断正式成绩 | 不自动发布 SDTI |

**代表输入（可替换，不是唯一场景）**

> 研究 HER2 阳性乳腺癌中 PIK3CA 突变是否影响治疗响应，并整理患者级科研数据集。

同一套流水线也可换题，例如肿瘤-正常表达、生存随访、试验登记检索。换题后改变的是 `ResearchSpec` 与选中队列，不是另写一套系统。

**已跑通的内部对照（用于证明能力，不是编造 Gold Set）**

| 变体 | 输入保持不变 | 系统实际行为 | 对能力的说明 |
|---|---|---|---|
| 仅生成检索计划 | 同一科研问题 | 输出研究方案与数据源规划，不访问外部库 | 证明「问题→方案」可单独验收 |
| 真实检索但结局不同域 | 同上 | METABRIC 848×46，生存/临床描述为主，治疗响应分析集为 0 | 证明质量门能拦住「有表但不同域」 |
| 结局同域、暴露不同患者 | 同上 | GSE76360 基线 50 例、48 例有治疗响应；公开矩阵无 PIK3CA | 证明能换队列补结局，且拒绝跨库贴突变 |
| 同患者暴露+结局完整包 | 同上 | cBioPortal `breast_alpelisib_2020`：同患者 PIK3CA 与治疗响应 | 证明查找目标是完整变量包，不是半成品队列 |

宽表中的 `—` 表示该公开队列未观测到该字段（如部分样本无 ERBB2 CNA）。年龄、分期、ER、PR 在 Alpelisib / MSKCC 2019 公开临床属性中本身不存在，系统 **不会** 用 METABRIC 的协变量贴到这些患者上；同队列可用协变量（性别、内分泌治疗、可测量病灶、在研周数）会进入研究设计。

## P5｜本作品采用的数据质量评价方法

### 实际评价方案

质量评价服务的是方向 1A 的「可分析、可追溯、可复用、发现错误后能修正」，而不是给某一道题打一个总分。评价分三层：

1. **发布准入（四层质量门）**：来源、字段、实体、科研适用性。决定结果能不能进入分析集。
2. **任务级诊断（与本工作台评测区同一口径）**：来源审计、结局完整、字段完整、请求要素覆盖、科研探索可用性。用于横向消融。
3. **冻结 SDTI**：公式已实现；Gold Set 未加载，成绩保持未评测。

### 实际采用的评价内容

| 实际采用的评价内容 | 具体评价方法 | 评价对象与样本 | 结果如何影响后续处理 |
|---|---|---|---|
| Gate 1 来源可信 | 检查 `source_id`、官方 URL、accession、checksum/本地缓存；URL 须落在 NCBI、GDC、cBioPortal、ClinicalTrials.gov、CIViC 等官方域名 | 当次任务已登记来源 | 缺 URL/`source_id` → REJECT；官方域名齐全 → PASS；否则 REVIEW |
| Gate 2 字段质量 | 主表非审计字段完整率、结局是否与问题匹配、标准化清洗次数 | 患者/样本级宽表 | 完整率 < 80% 或结局不匹配 → REVIEW |
| Gate 3 实体一致性 | 同一 `study_id` 内按原始 `patient_id`/`sample_id` 判定 MATCH / REVIEW / UNMATCH | 主表全部行 | UNMATCH/REVIEW 禁止跨患者、跨研究自动合并 |
| Gate 4 科研适用性 | 必需变量覆盖、结局同域（`response_domain`）、分析单位、样本量 | 研究方案必需变量 vs 主表 | 治疗响应不得用生存或细胞系 AUC/IC50 顶替 |
| 任务级诊断 | 来源审计完整度、结局完整率、字段完整率、请求要素覆盖、科研探索可用性 | 当前任务结果，前端「系统评测」同步展示 | 用于消融对照，不写成 SDTI |
| 冻结 SDTI | `docs/06_评测指标与SDTI.md` 几何平均 | 需冻结 Gold Set | 当前模板为空，一律写 **未评测** |

### 评价口径说明

**团队重点评价哪些方面，为什么：**  
重点评价系统是否具备方向 1A 的五项能力：找得到来源、解析得成字段、整合后可追溯、质量门能拦住错误、缺口出现后能换方法。代表案例只用来观察这些能力，不把「答对 HER2+/PIK3CA 题」当作评测目标。

**抽样数量、抽样方式和评价主体：**  
每次真实任务对当次全量来源与全量表做规则判定；评价主体为确定性质量门和任务级诊断，不是模型自行打分。冻结指标的人工抽检尚未开展（Gold Set 未加载）。内部对照用同一科研问题、不同模块开关（仅规划 / 真实检索 / 有无质量门 / 有无千问 / 单源 vs 多源）。

**正确、错误、缺失、冲突和无法判断分别如何定义：**

| 状态 | 定义 |
|---|---|
| 正确 / PASS | 有官方来源标识；字段与类型可核对；身份在同一研究命名空间内对齐；结局字段与问题同域 |
| 错误 / REJECT | 来源缺少 URL 或 `source_id`；或存在不可发布的安全冲突 |
| 缺失 | 主表无行、无结局字段、必需变量覆盖不足。建议协变量未发布标为「本队列未提供」，不记为系统失败 |
| 冲突 | 高权威来源对同一关键字段解释冲突时不自动选边，进入 review |
| 无法判断 / REVIEW | 证据不足、结局不匹配、Gold Set 未评、低置信度身份 |

**修正前后是否采用同一评价口径：**  
是。质量门和任务级诊断在检索补全前后使用同一套规则。缺口补全只允许再查公开库，不允许用知识库证据或另一项研究的患者字段填补当前患者。

## P6｜系统总体架构与数据闭环

### 本作品真实架构

系统按方向 1A 做成「问题输入 → 多源查找解析整合 → 质量闭环输出」三层。科研问题是可替换输入；Agent 在质量门失败时换方法，直到达标、科学上无法合法补齐，或达到轮次门限。

```text
科研问题（输入，可换题）
    ↓  千问 JSON Mode 或确定性解析
研究规格 ResearchSpec（人群 / 暴露 / 结局 / 数据类型）
    ↓  千问 Function Calling 或确定性规划
受控工具：GDC / GEO / GEO目录 / cBioPortal / ClinicalTrials.gov / CIViC / BioSample / Europe PMC
    ↓
原始表解析 → Canonical 字段 + raw_field/raw_value + source_id
    ↓
实体对齐（study 内 MATCH/REVIEW/UNMATCH，禁止无证据跨库并患者）
    ↓
四层质量门  PASS / REVIEW / REJECT
    ↓  观察 → 诊断 → 换方法 → 执行
迭代检索（默认 8 轮，上限 12 轮）
    ↓
分析矩阵 + 中文字段字典 + 质量报告 + 来源溯源 + 任务级诊断
    ↓ 导出
CSV / JSON / Parquet / Excel / Metadata / 质量报告
```

**智能体智能体现在何处：** 不是固定爬一个库，而是根据问题选择工具；观察到结局不同域或必需变量缺口后，更换尚未尝试的公开入口；选队列时优先同患者同时具备暴露和结局的完整包。

**人工职能配合：** 研究者只提供问题和 REVIEW 决策；千问负责理解与规划；规则层负责医学安全和发布准入。人和模型都不能绕过质量门去「补全」无来源字段。

### 实际模块

| 实际模块 | 输入 | 本作品的核心处理 | 输出 | 与下一模块的关系 |
|---|---|---|---|---|
| 科研数据需求理解 | 自然语言研究问题 | PICO 解析；HER2 与 ERBB2 检测维度不混同 | `ResearchSpec` / 解析卡片 | 约束后续检索与变量清单 |
| 数据源发现与筛选 | Spec、入口上限、本轮观察 | 函数调用或确定性规划选择工具；GEO 目录与文献收割新 GSE | 工具调用计划、候选登记 | 未注册函数不可调用 |
| 多类型内容解析 | 接口 JSON、GEO Series Matrix 等 | 临床透视、突变/CNA 转宽表；真实样本特征解析 | 原始+标准化表 | 临床样本锚定队列，孤立分子记录不扩成假患者 |
| 字段对齐与多源整合 | 多表、多来源 | Schema 匹配；同一研究内身份对齐；同队列协变量保留，跨研究协变量不贴值 | 患者/样本级宽表 | 跨库编号相同不等于同一患者 |
| 质量检查与反馈修正 | 宽表、来源、研究方案 | 四层质量门；缺口驱动补搜 | PASS/REVIEW/REJECT、缺口清单、诊断指标 | 未 PASS 则分析数据集不放行 |
| 结构化输出 | 通过或待审查的任务结果 | 字典、溯源、导出、系统评测 | 可下载科研数据资产 | 供后续统计/图谱/证据推理，不作诊疗 |

### 数据闭环的关键设计

本作品不是一次性检索摘要。质量门 REVIEW 后，Agent 观察主表、结局域和分子覆盖，诊断缺口，再检索尚未尝试的公开入口。默认 8 轮、上限 12 轮；没有新入口则停止，并把缺口写成可审计结果。

内部对照说明闭环有效：METABRIC 有分子、无同域治疗响应 → 分析集 0；随后换 GSE76360 补上响应结局，但拒绝把 METABRIC 的 PIK3CA 贴到 GEO 患者；再切换到同患者同时含 PIK3CA 与治疗响应的 Alpelisib 队列。这是方向 1A 要求的「发现错误后修正」，不是针对单题调参。

**本作品最终形成的主要数据成果：**  
任务级患者/样本宽表、中文字段字典、来源清单（URL/accession/checksum）、四层质量门报告、任务级诊断与消融表、可导出 Metadata 与质量报告。

**已经实际处理的数据来源和任务范围：**  
真实数据模式已接入并实际请求：cBioPortal、NCBI GEO、GDC、ClinicalTrials.gov/AACT、CIViC；发现层含 BioSample、Europe PMC。GTEx、OncoKB 等仅出现在数据源规划中，不生成虚假记录。

**相较通用检索或人工复制整理的主要不同：**  
通用检索返回文献或网页；本作品输出带 `source_id` 与原始值的宽表，并用质量门决定能否进入分析。人工复制难以系统执行 HER2 IHC 2+ 不自动判阳、细胞系药敏与患者疗效分域、禁止跨库贴协变量等硬规则。

## P7｜Qwen 使用方式与上下文工程

### Qwen 在本作品中的实际作用

| 内容 | 本作品实际做法 |
|---|---|
| 使用的 Qwen 模型与调用方式 | 默认 `qwen-plus`；阿里云百炼 OpenAI 兼容 `chat/completions`。前端可建最长 2 小时内存会话（只传 `qwen_session_id`，Key 不落盘、不进任务结果）。支持 JSON Mode 与 Function Calling |
| Qwen 承担的具体任务 | （1）把任意科研问题解析为 `ResearchSpec` JSON；（2）从已注册工具中选择数据源并填参数；（3）根据观察到的缺口再规划下一步；（4）仅根据系统给出的已验证统计写中文摘要 |
| 一次查找时提供给模型的上下文 | 科研问题；允许的 JSON 字段与医学约束；当前 Spec；已注册工具 schema；工具返回摘要；已验证行数/列数/结局匹配；质量门事实。不把原始患者表整表送入模型生成新事实 |
| 结构化输出或字段约束 | `response_format=json_object`；Spec 经 Pydantic 校验；工具参数再经 Adapter 校验 accession、域名、记录上限 |
| 与检索、解析、数据库工具的协作 | 模型只发工具名与参数；真实 HTTP/解析由 Adapter 执行；医学安全规则与质量门不由模型覆盖 |

问题在系统里等价于一次任务输入。换一道题只需改问题文本，不必改架构。千问不可用时确定性规划兜底，结果标明 `used_qwen`，保证对照实验可重复。

### 上下文组织（结构示意）

```text
system: 科研数据规划器 / 摘要器（禁止虚构队列事实）
user: { 科研问题, JSON字段约定, 医学约束 }
assistant: ResearchSpec JSON
user: { research_spec, max_sources, 只调用已注册函数 }
assistant: tool_calls
tool: { 记录数、accession、官方URL、失败原因 }     ← Adapter，非模型编造
user: { 已验证统计, 可科研性报告 }
assistant: { summary }   ← 只能复述 JSON 中的统计
```

**团队为减少无来源生成、字段错配或错误合并采取的措施：**

- 未注册函数不可调用；工具参数二次校验。
- 摘要禁止把工具原始记录数称为患者数，禁止补写 JSON 中不存在的亚型/治疗/突变。
- HER2 IHC 2+ 不得直接判为阳性；ERBB2 CNA amplification 不等于 IHC 阳性。
- 细胞系 `AUC/IC50` 与患者 `pCR/response` 用 `response_domain` 区分。
- 低置信度患者匹配进入 REVIEW/UNMATCH，不自动合并。
- 其他研究的年龄/ER/PR 不得贴到当前患者。

**上下文在查找、解析和修正前后如何更新：**  
解析后写入 Spec；工具执行后追加 tool 摘要；质量门与缺口清单进入收集模块，用于下一轮工具参数，而不是让模型直接改宽表单元格。

**该设计对数据结果带来的实际变化：**  
同一输入下，仅规划得到方案、真实检索得到可审计宽表；质量门把结局不同域的 METABRIC 拦住；换方法后能形成治疗响应队列，并进一步选择同患者完整变量包。千问主路径负责理解和再规划，确定性规划保证无 Key 时仍可对照。

## P12｜质量检查与实际反馈修正机制

### 已发现或主动测试过的质量问题

| 实际质量问题 | 系统如何发现 | 原因分析 | 实际修改的环节 | 修正后的结果 | 反馈如何改变数据流程 |
|---|---|---|---|---|---|
| 研究结局与问题不匹配 | Gate 2/4：`target_match=false` | METABRIC 主结局偏生存，不是治疗响应 | 不改原始生存字段含义；分析集保持 0 | 触发补搜含响应的队列 | 不用 OS 冒充响应 |
| 半成品队列（有结局无暴露） | 必需变量覆盖 + 同患者双特征选择 | GSE76360 有响应、公开矩阵无 PIK3CA | 禁止跨库贴突变；改选同患者完整包 | 切到 Alpelisib 等双特征队列 | 查找目标升级为完整变量包 |
| 建议协变量未发布 | 研究设计区分必需 / 建议 | Alpelisib、MSKCC 2019 公开属性无年龄/分期/ER/PR | 不从 METABRIC 贴值；列出同队列可用协变量 | 界面标「本队列未提供」，不记系统失败 | 保留科学边界 |
| 宽表出现 `—` | 空值不填野生型 | 该样本在原研究未测 CNA/变异 | 保留缺失，不编造 | 导出仍带原始空值 | 缺失可审计 |
| 孤立分子记录 | 临床样本锚定 | mutation/CNA 无法连到临床样本 | 排除计数，不扩成新患者 | 降低假高缺失率 | 整合阶段硬约束 |
| 无证据跨库并患者 | 实体对齐命名空间 | 不同库 patient_id 字符串相同 | MATCH 仅限同一 study + 原始编号 | 跨库保持 UNMATCH | 冲突走 REVIEW |

**哪些问题触发重新查找来源：**  
必需变量覆盖不足、结局同域失败、质量门未 PASS，且仍有公开库动作可执行（默认 8 轮、上限 12 轮未用尽）。

**哪些问题触发重新解析、字段对齐或单位换算：**  
同一来源内 raw 值可标准化；单位/编码冲突进入 review，不静默换算成临床结论。内分泌治疗不等于 ER 阳性。

**哪些问题必须交由研究者或人工审核：**  
HER2 IHC 2+；高权威来源不可解释冲突；低置信度身份；Gold Set / SDTI；建议协变量原研究未发布时是否改题或另选队列。

**团队如何保留修正前后的真实数据差异：**  
主表保留 `raw_field`/`raw_value`/`raw_characteristics`；导出含原始信息视图；清洗动作与消融表写入报告。不覆盖底层缓存 JSON。

## P17｜第二版输出与迭代变化

第二版及后续换方法用来证明方向 1A 的修正能力：同一输入、同一评价口径，系统能根据缺口更换数据源和解析策略。

### 第一版与后续版本的实际变化

| 变化内容 | 第一版结果 | 发现的问题 | 实际修改的方法 | 后续结果 |
|---|---|---|---|---|
| 数据源选择 | METABRIC 宽表 | 缺治疗响应同域结局 | 质量门 REVIEW 后换独立响应队列 | GSE76360：48 例有治疗响应 |
| 完整变量包 | 有分子无响应，或有响应无同患者突变 | 半成品队列不能支持原问题 | 优先选择同患者双特征队列 | Alpelisib：PIK3CA 与治疗响应同患者 |
| 字段对齐 | 空列曾被当成已覆盖 | 覆盖率虚高 | 空列不再计入必需覆盖 | 必需变量按真实取值计算 |
| 协变量 | 用固定年龄/ER 清单判缺失 | 把原研究未发布字段当成系统失败 | 同队列有则整合，无则标未提供，禁止跨库贴值 | 性别、内分泌治疗等可用来源进入设计表 |
| 结构化输出 | 848×46 可导出，分析集 0 | 漏斗第三段为 0 | 换方法直到完整包或合法方法用尽 | 输出可分析宽表 + 溯源 + 诊断指标 |

**第二版相较第一版实际改善了什么：**  
从「有表但不能分析」变成「能按问题换队列，并保住来源与医学边界」。这是查找-解析-整合-修正闭环，而不是把生存改名为响应。

**哪些问题没有解决或出现了新的代价：**  
公开队列若未发布年龄/分期/ER/PR，系统不会编造。代价是协变量可能不全；收益是结果可追溯、不会把不同研究的患者拼成假队列。宽表中的 `—` 保留为真实未观测。

**后续数据能够支持什么分析：**  
同患者 PIK3CA × 治疗响应的描述与分组比较；来源审计；字段字典复用。不能支持把其他研究的 ER/PR/年龄当作这些患者的协变量，也不能把细胞系药敏当作患者疗效。

**是否达到团队设定的质量要求，依据是什么：**  
已达到方向 1A 对「可查找、可解析、可整合、可追溯、可修正」的实现要求。正式 SDTI 仍未评测，依据是 Gold Set 未加载。

## P18｜实际对照、消融与方案优势

对照目的：证明的是 **模型的分析与整合能力**，不是某一条乳腺癌结论。评价方法与本工作台评测区一致：任务级诊断 + 内部消融；冻结 SDTI 保持未评测。

### 团队实际完成的比较

| 实际比较对象 | 保持相同的数据需求 | 采用的评价方法 | 本作品结果 | 对照结果 | 结论与代价 |
|---|---|---|---|---|---|
| 完整系统 vs 仅规划 | 同一科研问题作为输入 | 是否访问公开库、是否形成可审计宽表、来源审计是否可计算 | 真实检索形成宽表、官方来源、质量门和诊断指标 | 仅输出研究方案与数据源规划 | 完整系统打通「问题→数据资产」；规划模式可单独验收需求理解 |
| 完整系统 vs 去掉质量门（METABRIC 宽表直出） | 同上 | 结局是否与问题同域、分析集是否放行、请求要素覆盖 | 质量门拦住不同域结局，并换方法到响应队列/完整包 | 直出 848×46 时看起来字段多，但不能做治疗响应 | 质量门把「有表」升级为「适合该问题」 |
| 完整系统 vs 去掉多源/换方法 | 同上 | 数据源多样性、是否停在半成品队列 | 能从 GEO 响应队列再切到同患者双特征队列 | 单源或停在第一张表则暴露与结局无法同患者对齐 | 多源整合的价值是完整变量包，不是堆来源名称 |
| 完整系统 vs 去掉来源图谱 | 同上 | 来源审计完整度、官方 URL、raw 值是否可回看 | 每个来源可点回官方地址，导出保留 `source_id` | 只看表格时无法复核字段从哪来 | 可追溯是方向 1A 硬条件 |
| 千问智能体 vs 确定性规划 | 同上 | 问题解析、工具选择、观察后再规划 | 千问主路径完成 Spec 与函数调用；无 Key 时确定性兜底并标明 `used_qwen` | 规则规划稳定但复杂换题理解较弱 | 二者共享 Adapter、质量门与评测，对照可重复 |

### 结果说明

**科研数据适用性方面，本作品实际改善了什么：**  
适用性写成四层质量门和任务级诊断，使任意科研问题都能被验收为「能否支持该分析」，而不是返回一堆相关网页。

**数据处理方法方面，本作品实际改善了什么：**  
形成「问题解析 → 真实检索 → 标准化与同研究对齐 → 质量门 → 换方法」完整链；原始值与标准化结果一并保留；协变量只整合同队列真实字段。

**结果质量和复用方面，本作品实际改善了什么：**  
中文字段字典、官方溯源、CSV/JSON/Parquet/Excel/Metadata/质量报告导出，以及本工作台评测区的诊断指标和消融表，便于后续科研分析、影响力评估或证据推理。

**没有改善的部分及增加的成本：**  
冻结 Gold Set 未加载，正式 SDTI 未评测，不使用页面 AI proxy 冒充成绩。公开队列未发布的患者级协变量不会被补全。代价是检索轮次和人工 REVIEW 增加；收益是结果可复核、可复用、不会伪造完整表。
