# 数据统一与患者/样本身份对齐

## 当前结论

系统只在可审计的身份命名空间内进行对齐：

```text
study_id + 来源研究内原始 patient_id / sample_id
```

这意味着：

- 同一研究内，患者临床、样本临床和分子记录可以按原始 `patient_id`、`sample_id` 对齐。
- `sample_id` 不能被当作 `patient_id` 使用；一个患者可以有多个样本。
- 不同数据库中的相同字符串编号不自动代表同一个患者。
- `source_id` 标识文件、接口资源或证据项，不是患者身份标识。
- GDC、GEO、cBioPortal 等不同研究空间不会仅凭编号直接横向合并。
- BioSample、Europe PMC 这类发现层来源只补充样本元数据和文献语境，不参与患者表拼接。

## 主流程行为

当前 `ResearchAgentService` 会先选择一份与研究变量和结局最匹配的主科研数据集。其他来源可以进入来源审计和补搜报告，但不会直接把患者行拼进主表。

数据集构建阶段：

1. 以临床样本表作为 cBioPortal 队列锚点。
2. 用 `sampleId` 优先连接突变和拷贝数记录。
3. 只有在患者唯一对应一个样本时，才允许使用 `patientId` 回退连接。
4. 无法连接的分子记录进入孤立记录计数，不被补成野生型或新患者。
5. GEO 患者编号使用 `accession-subject` 隔离命名空间，并保留原始 `sample_id` 和 `raw_characteristics`。

## 页面审计

主科研数据页面的“数据统一与身份对齐”区域会展示：

- 患者编号和样本编号覆盖率；
- 主表中的研究编号是否一致；
- 主表行级 `source_id` 是否一致；
- 已检索来源与真正进入主表来源的区别；
- 未执行跨来源患者合并的明确状态；
- 缺失身份、重复身份和来源冲突的限制说明。

“同一研究内可对齐”不等于“所有公开数据库已经证明是同一批患者”。跨来源身份映射必须另有可审计的映射表、原始研究说明或人工复核证据，否则保持 `unresolved/review`。
