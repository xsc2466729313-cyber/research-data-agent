# 从科研问题到可用数据：乳腺癌精准治疗科研数据智能体的设计与验证

> 参赛方向：方向 1“科学数据整合与影响力分析应用”·A“科学数据查找、解析与整合”  
> 项目名称：乳腺癌精准治疗科研数据智能体  
> 文档版本：2026-09-02（公开基准更新终版）
> 结果口径：正文聚焦当前最佳综合结果与真实 Qwen 字段匹配结果；公开模块逐任务对照见 [`公开数据集统一对照报告`](../evaluation/PUBLIC_DATASET_COMPARISON_20260902.md)。

## 参赛作品简介

本项目面向乳腺癌公开科研数据整合：把自然语言研究问题整理成可执行的数据需求，再从真实来源取得记录，按研究分别建表，保留来源、原字段和原值，并通过医学安全规则与四层质量门控制发布边界。系统不生成诊疗建议，只输出可核查、可复用的科研数据包。

## 摘要

系统围绕“研究问题 - 来源发现 - 真实取数 - 字段标准化 - 患者/样本关联 - 质量门 - 导出交付”构建闭环。千问负责问题理解与来源规划，固定数据接口负责从 GEO、GDC、cBioPortal、AACT、CIViC、DepMap 和论文表图注中取得真实记录，规则层负责字段归一、身份核验和医学安全守门。最终结果只保留当前最佳综合分与真实 Qwen 字段匹配分。

## 1 系统设计

### 1.1 总体思路

系统将研究问题拆成研究对象、分子变量、治疗阶段、疗效与必要字段五部分，再按来源分工把不同数据库与论文材料组织成主表和补充表。能比较的字段先统一中文标准值，能回查的关键值保留原字段和原值；不能安全连接的患者/样本记录继续分开保存。

### 1.2 质量边界

系统采用四层质量门：来源可信、字段质量、实体一致性、科研适用性。只要关键来源、关键字段或患者/样本关联无法核实，就不把结果写成正式结论。医学安全规则保持不变，包括 HER2 IHC 2+ 不直接判阳、ERBB2 CNA 不等同 HER2 IHC positive、细胞系药敏与患者 response 区分 `response_domain`。

## 2 最终结果

| 指标 | 结果 | 说明 |
|---|---:|---|
| 当前最佳综合结果 | **SDTI 100.00** | `official-candidate-current-deterministic-baseline-20260902` |
| 真实 Qwen 字段匹配 | **Macro F1 0.9018** | Valentine 10 个任务，`qwen3.8-max` |
| 公开问题解析 | **Macro span F1 0.5522** | EBM-NLP professional test，PICO sequence v4 |
| 公开科学检索 | **Macro nDCG@10 0.3920** | BEIR 五任务，开发集选择 BGE/CrossEncoder |
| 公开数据清洗 | **Macro Cell F1 0.9169** | Raha/HoloClean 六任务，source-anchor v6 |

当前最佳综合结果来自正式 Gold Set 上的当前基线运行；其余结果来自公开能力层测试，分别使用各自官方划分与指标，不混成一个总分。清洗 v6 在不读取 clean 表的条件下利用重复记录中的来源锚点，使 Flights Cell F1 从 `0.1811` 提升到 `0.9650`，六任务宏平均从 `0.7863` 提升到 `0.9169`；该优势只适用于存在可验证重复键和来源锚点的数据。EBM-NLP 问题解析仍受干预短语边界影响，BEIR 检索的强重排则增加约 171 ms/query 延迟。

### 2.1 公开数据集对照与瓶颈解释

完整结果、逐任务指标、消融实验、Qwen SciFact 查询改写条件实验和实体匹配对照统一记录在 [`evaluation/PUBLIC_DATASET_COMPARISON_20260902.md`](../evaluation/PUBLIC_DATASET_COMPARISON_20260902.md)。结果显示，问题解析的主要短板是 Interventions span 边界，科学检索的主要短板是领域差异、候选召回和轻量通用嵌入对 SciDocs/ArguAna 的适应性；Qwen 在已完成的字段匹配和 SciFact 查询改写中有明显收益，但 API 未完整覆盖的问题解析/清洗运行只保留审计，不计入主成绩。

本次公开数据集统一复测结果如下。各能力层使用各自公开数据集的官方测试划分和通用指标，不把不同层分数相加，也不将通用数据集结果外推为乳腺癌临床结论。

| 能力层 | 公开数据集 | 当前方法 | 核心指标 | 结果 |
|---|---|---|---|---:|
| 问题解析 | EBM-NLP professional test | PICO sequence v4 | Macro span F1 | **0.5522** |
| 科学检索 | BEIR 五任务 test | 开发集选择 BGE/CrossEncoder | Macro nDCG@10 | **0.3920** |
| 字段匹配 | Valentine 十任务 | Qwen-assisted | Macro Schema F1 | **0.9018** |
| 实体匹配 | DeepMatcher 五任务 test | learned entity fusion | Macro Entity F1 | **0.7449** |
| 数据清洗 | Raha/HoloClean 六任务 | source-anchor v6 | Macro Cell F1 | **0.9169** |

问题解析的消融结果为：词典 v2、上下文 v3、序列特征 v4 的 Macro span F1 分别为 `0.4662`、`0.4900` 和 `0.5522`。v4 将 Participants、Interventions、Outcomes 的 F1 分别提升到 `0.5931`、`0.4660`、`0.5975`，但 Interventions 仍是主要瓶颈。其原因是 EBM-NLP 评价的是医学摘要中的 token span 边界，而不是普通问答或 ResearchSpec 字段准确率；复合干预、剂量疗程、比较句和否定句使轻量词组与局部序列特征难以恢复完整干预范围。

科学检索在 BGE 单路基础上使用开发集选择器，在 SciFact 和 NFCorpus 选择 CrossEncoder，在没有可用开发标注的 SciDocs 和 ArguAna 固定使用 BGE，在 FiQA 保留 BGE。Macro nDCG@10 从 `0.3880` 提升到 `0.3920`，Macro MRR@10 从 `0.4421` 提升到 `0.4504`，Recall@100 保持 `0.6554`。SciDocs 和 ArguAna 的复杂论文语义/论证关系、通用嵌入的领域差异以及候选召回限制，解释了检索没有全面超过公开基线；重排平均延迟约 `171 ms/query`，因此生产链路按风险和延迟预算选择策略。

数据处理方面，source-anchor v6 仅利用 dirty 表自身的 `flight`、`src`、重复键和同组唯一非空值，不读取 clean 表。六任务 Macro Cell F1 从 v5 的 `0.7863` 提升到 `0.9169`，其中 Flights 从 `0.1811` 提升到 `0.9650`；Rayyan 仍为 `0.7797`，因为字符损坏和缺失语义信息没有足够的表内证据安全恢复。

真实 Qwen 条件实验也单独记录。Valentine 字段匹配由 `qwen3.8-max` 完成 `10/10` 个任务，Macro F1 为 `0.9018`，相对项目 Schema Matcher v3 的 `0.7994` 提升 `+0.1024`；收益主要来自缩写、后缀和语义改名，但三个任务低于规则方法。BEIR SciFact 查询改写实验中，Qwen rewrite + BM25 的 nDCG@10 为 `0.6453`，BM25 为 `0.6040`，提升 `+0.0413`；300 次调用中 264 次成功、36 次原查询回退。问题解析和清洗的 Qwen 全量运行因网络/结构化输出不稳定未形成完整覆盖，故不计入主结果。

## 4 结论

本项目已经把自然语言科研问题收束成可追溯的数据包，并以当前最佳综合结果 SDTI 100.00、真实 Qwen 字段匹配 Macro F1 0.9018，以及公开问题解析、检索、清洗三层的真实统一测试结果作为展示依据。未完整成功的 Qwen API 批次只保留失败审计，不计入模型成绩。
