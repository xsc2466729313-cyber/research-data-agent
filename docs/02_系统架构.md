# 02 系统架构

架构图与流程图只放在本文件中，不在前端页面展示。系统运行时仍按图中闭环换方法，直到主目标达成或合法方法用尽。

三层流水线把科研问题变成可审计数据集；内层 Agent 在质量门失败时更换尚未尝试的方法。

## 智能体换方法闭环

```mermaid
flowchart TD
    Q["科研问题"] --> P["千问规划：解析问题并选择工具"]
    P --> X["执行公开数据库工具"]
    X --> O["观察：主表、结局域、队列"]
    O --> D{"诊断改进方向"}
    D -->|"需要患者主表"| S1["换可解析队列"]
    D -->|"需要治疗响应"| S2["切换含治疗响应的独立队列"]
    D -->|"需要同队列分子变量"| S3["检索目录与文献中的独立研究"]
    D -->|"需要临床协变量"| S4["补充官方临床表"]
    S1 --> X
    S2 --> X
    S3 --> G{"仍有可执行策略且未达轮次门限"}
    S4 --> X
    G -->|"继续"| X
    G -->|"输出当前最佳数据包"| Z["形成可导出、可溯源的科研结果"]
    D -->|"目标已满足"| PASS["进入质量门汇总与导出"]
```

代表案例：METABRIC 有 PIK3CA、无治疗响应 → 诊断为结局域失败 → 切换 GSE76360 响应队列。该队列没有同患者 PIK3CA 时停止，不把 METABRIC 突变贴到 GEO 患者上。
