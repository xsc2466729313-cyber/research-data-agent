# 指标提升与两轮融合说明

## 结论

本轮只在原有公开数据、原有测试切分和原有指标上改进，没有降低质量门阈值，也没有把内部候选分数写成正式成绩。

| 模块 | 提升前 | 提升后 | 变化 | 改进方式 |
|---|---:|---:|---:|---|
| 科学检索 | 0.3791 | 0.3791 | 0 | 保持原融合口径，避免测试集调权重 |
| 字段匹配 | 0.7994 | 0.7994 | 0 | 保持原 V3 口径 |
| 实体匹配 | 0.5579 | **0.7449** | **+0.1870** | 在 train/valid 选择 V2、V3 或 AND，test 盲测 |
| 数据清洗 | 0.3937 | **0.5726** | **+0.1789** | 格式归一化 + 高频 `x` 占位符一致性修复 |

四个模块属于不同公开任务和指标，不能相加。提升后实体融合略高于 RecordLinkage 对照 `0.7440`；清洗仍落后 Raha 子集 `0.8159`，因此没有宣布整体领先。

## 实体匹配：两种视图的自适应融合

第一种视图是已有的 V2 规则学习器，利用标题、字符、包含关系和支持字段；第二种视图是 V3 生产匹配器，包含 blocking 和患者/样本安全门。每个数据集仅在训练/验证集比较三种固定策略：

- `v2`：只采用 V2 提案；
- `v3`：只采用 V3 提案；
- `and`：两种视图都同意才提出候选。

测试集只执行验证集选出的策略。当前选择结果为：Amazon-Google=`and`、Beer=`v2`、DBLP-ACM=`v3`、Fodors-Zagats=`and`、Walmart-Amazon=`v2`。这解释了为什么 Beer 不再被 V3 的 0 分拖低，同时仍保留生产安全门。

## 数据清洗：格式与占位符融合

原 `format-profile v2` 能处理数值、时间、缺失标记和城市/州拼接；新增的 placeholder consensus 只使用 dirty 表中同列的高频值。当异常值包含 `x` 占位符时，只有在字符长度一致、所有非 `x` 字符一致且频次有明显优势时才替换。它不读取 clean 标签，不推断医学语义，也不会覆盖原方法已经做出的修复。

Hospital 的错误单元检测从 `0.0000` 提升到 `0.8947`；Beers `0.9837`、Movies `0.9066` 保持；Flights `0.0781` 和 Rayyan `0.0000` 仍是下一轮短板。双方共同五集宏平均由 `0.3937` 提升到 `0.5726`。

## 两轮闭环如何合并

闭环响应保留第一轮和第二轮的输入、工具调用、诊断、指标快照和哈希。展示层最多显示两轮；最终数据结果不简单取最后一轮，而是按以下顺序选择最佳轮次：

1. `publish_allowed` 与安全门状态；
2. 目标字段匹配率；
3. 协议必选字段覆盖率；
4. 任务进度与未解决缺口数。

因此第二轮只有在指标确实改善时才替换第一轮结果；如果第二轮引入更多冲突或未解决缺口，系统保留第一轮的最佳结果，同时在报告中记录第二轮已尝试的补搜动作。该机制是“取优合并”，不是把不同队列的患者行直接拼接。
