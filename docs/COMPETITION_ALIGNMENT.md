# 赛道二方向1A比赛对齐说明

## 定位

本项目面向 2026 年度中国青年科技创新揭榜挂帅擂台赛的赛道二数据场景，方向1A“科学数据查找解析与整合”。实现重点不是只返回一批检索结果，而是把乳腺癌精准治疗科研问题转成可追溯、可审计、可下载、可继续建模的患者/样本级科研数据资产。

本说明用于提交材料和演示串讲。它描述当前系统如何对齐比赛模板要求，但不替代 `docs/06_评测指标与SDTI.md` 中的冻结评测公式，也不生成没有 Gold Set 支撑的官方成绩。

## 诊断指标

比赛对齐报告中的指标是任务级诊断指标，用于说明当前结果是否具备科研适用性；它们不是官方 Gold Set Precision/Recall/SDTI 成绩。正式成绩仍必须通过冻结 Gold Set 和 `docs/EVALUATION_SDTI.md` 的流程计算。

| 指标 | 含义 | 设计目的 |
|---|---|---|
| 来源可追溯率 | 已登记来源中同时具备 `source_id` 与官方 URL 的比例 | 衡量可复核性 |
| 结局完整率 | `1 - target_missing_rate` | 判断是否能做响应/生存等结局分析 |
| 字段完整率 | 主科研数据集非审计字段的完整程度 | 发现宽表缺失风险 |
| 请求变量覆盖率 | 用户问题中关键基因/变量在主数据集中的覆盖比例 | 衡量问题和数据的匹配程度 |
| 数据源多样性 | 当前联通数据库类型数相对系统支持的比例 | 展示多源查找和交叉验证能力 |
| 分析可用性 | `readiness.analysis_ready` 的布尔诊断 | 防止把过程演示误说成可发表结论 |
| 内部综合诊断分 | 对可计算诊断项取均值后转为 0-100 | 方便演示横向比较，但不作为官方成绩 |
| 自动清洗值数 | 本次标准化/清洗动作计数 | 展示修正闭环 |
| 孤立分子记录排除数 | 未能连接到临床队列的 mutation/CNA 记录数 | 避免分子孤立记录制造假患者 |
| 重复样本行 | 重复样本或重复观测计数 | 提醒分组和泄漏风险 |

## 混合 RAG 设计

系统采用四层混合 RAG：

1. 词法/关键词层：从科研问题抽取疾病、基因、药物、结局和 accession 候选。
2. 语义/千问规划层：千问生成 `ResearchSpec`，并通过 Function Calling 选择受控工具。
3. 结构化/规则层：Pydantic Schema、医学安全规则、来源上限和质量门控共同约束结果。
4. 图谱/证据层：候选来源、真实来源、主科研数据集、字段字典和质量反馈形成 lineage 图。

这套设计的核心是把“生成”和“事实”分开：千问负责理解、规划和总结，事实来自公开数据库 Adapter，医学安全和发布门控由确定性规则执行。

### RAG 库匹配可视化

前端新增“RAG 库匹配可视化”，将每个候选数据库/数据集与科研问题拆成可解释的匹配信号：候选检索相关度、疾病语义、分子数据、治疗字段、结局字段、数据类型和公开访问。每行同时标注数据编号、数据类型、样本/记录规模、是否已进入本次来源结果以及保留为候选或待复核的理由。

该匹配分是任务级诊断分，用于展示候选库选择逻辑，不是 Retrieval Precision、Recall、Gold Set 或 SDTI 成绩。没有真实字段证据的信号不会被自动写成“命中”；候选库仍需经过来源审计、字段解析和医学安全门控。

## 知识图谱实现

当前知识图谱是来源-数据集-字段-质量反馈图，重点服务科学数据整合和审计：

| 节点类型 | 示例 |
|---|---|
| 科研问题 | HER2 阳性乳腺癌 PIK3CA 与新辅助治疗响应 |
| 工具 | `search_geo`、`search_cbioportal` |
| 来源项 | GSE76360、METABRIC、TCGA-BRCA 等 |
| 主科研数据集 | 患者/样本级宽表 |
| 字段 | `treatment_response`、`pik3ca_mutation`、`source_id` |
| 质量反馈 | 结局缺失、变量未覆盖、孤立分子记录排除 |

图中的边表示检索、选择、来源归属、字段解释和反馈关系，不表示不同数据库患者被自动合并。低置信度患者/样本关联必须进入 unresolved/review，不能由图谱强行连接。

## 消融与对比方案

建议提交时使用同一科研问题、同一数据上限、同一网络环境和同一导出格式进行对比，避免把运行波动当成模型改进。

| 实验 | 关闭内容 | 观察指标 | 预期变化 |
|---|---|---|---|
| 完整系统 | 千问 + 多源工具 + 规则过滤 + lineage 图 | 全部诊断指标 | 作为主结果 |
| 去掉千问结构化解析 | `use_qwen=false` | 请求变量覆盖率、工具选择准确性、总结质量 | 复杂问题理解能力下降 |
| 去掉多源融合 | `max_sources=1` 或只保留单一 Adapter | 数据源多样性、字段完整率、候选覆盖 | 证据互证和变量补充能力下降 |
| 去掉来源图谱 | 只看表格，不展示 lineage | 来源可追溯率、人工复核耗时 | 结果可解释性下降 |
| 去掉修正闭环 | 不执行清洗/排除/风险提示 | 自动清洗值数、重复样本行、风险提示 | 数据科研适用性下降 |

可加入外部基线：普通关键词检索、单数据库下载脚本、未启用 Qwen 的确定性规划、其他开源 RAG 框架。所有基线都只能使用真实运行结果，不得填入虚构分数。

## 提交材料建议

20 页以内技术方案可按以下结构组织：

1. 题目与场景：赛道二方向1A，乳腺癌精准治疗科研数据整合。
2. 科研痛点：多源分散、字段异构、来源难追溯、结局和分子变量不同域。
3. 总体架构：千问 Agent、受控 Adapter、标准化融合、质量门控、可视化。
4. 混合 RAG：四层检索增强与事实边界。
5. 知识图谱：来源-数据集-字段-反馈图。
6. 代表案例：HER2 阳性乳腺癌中 PIK3CA 与新辅助治疗响应。
7. 指标体系：官方 SDTI 边界 + 任务级诊断指标。
8. 消融实验：完整系统与去掉关键模块的对比。
9. 结果展示：前端截图、Excel 导出、API 响应。
10. 局限与下一步：Gold Set、更多数据解析器、人工复核队列。

## 运行和验证

常用验证命令：

```powershell
$env:PYTHONPATH="."
python -m pytest -ra
node --check frontend/app.js
```

推荐演示入口：

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

随后打开前端首页，连接千问 API，运行默认科研问题，检查“可科研性检查”“数据溯源”“比赛对齐与消融”和 Excel 导出的 `比赛报告` sheet。
