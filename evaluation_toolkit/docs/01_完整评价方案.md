# 01 完整评价方案

## 1. 评价目标

评价体系必须同时回答四个问题：

1. **会不会清洗？** —— 外部 Cleaning Benchmark。
2. **会不会找到真正相关的科学内容？** —— 外部 Retrieval Benchmark。
3. **会不会把不同来源正确对齐、关联和整合？** —— Schema Matching + Entity Matching Benchmark。
4. **最终形成的数据是否适合当前科研目的？** —— Task-Adaptive Fitness-for-Purpose。

此外，用 Quality Gate 约束真实科研数据进入最终结构化结果的资格，并用消融实验证明其有效性。

---

## 2. Stage A：数据清洗能力

### 2.1 数据
主实验：
- Hospital
- Flights
- Beers

扩展：
- Rayyan
- Movies

这些数据存在 dirty/clean 对或可获得 Ground Truth，因此无需给自己的真实科研数据大规模人工标注。

### 2.2 对比方法
建议最少：
- HoloClean：经典概率式数据修复
- Raha + Baran：配置无关的错误检测/修复
- Cocoon：LLM 数据清洗
- Our Agent

可选：
- LAED：LLM-agent 表格错误检测
- ED2：主动学习错误检测

### 2.3 主指标

设真实错误 Cell 集合为 G，系统预测错误 Cell 集合为 P：

Precision = |G∩P| / |P|

Recall = |G∩P| / |G|

F1 = 2PR / (P+R)

**解释：**
- Precision 高：系统少把正常 Cell 当成错误。
- Recall 高：系统少漏掉真正错误。
- F1 高：误报和漏报之间综合更好。

若评价“修复”而非只评价“检测”，必须统一 benchmark 协议：只有修复到 Ground Truth 正确值才计成功。

### 2.4 域内验证
在 GDC/GEO/cBioPortal 的结构化真实记录上自动注入：
- 缺失
- typo
- 格式错误
- 单位变换
- 重复
- 字段别名
- patient/sample ID 扰动

由于污染由程序生成，原值即 Ground Truth。该实验用于证明公开 Benchmark 能力可迁移到科研域。

## 3. Stage B：科学数据检索能力

### 3.1 数据
主：
- BEIR SciFact：科学事实/论文检索，300 test queries、约5K corpus。

补充：
- BEIR NFCorpus：生物医学/营养信息检索，323 test queries、约3.6K corpus。

### 3.2 对比方法
- BM25：词法基线
- Contriever-MS MARCO：经典稠密检索
- BGE-M3：现代多功能检索模型
- Qwen-only Retrieval
- Our Full Agent Retrieval

### 3.3 主指标
nDCG@10：

DCG@K = Σ_i (2^{rel_i}-1) / log2(i+1)

nDCG@K = DCG@K / IDCG@K

主报告 nDCG@10，辅助报告 Recall@100、MRR@10、平均延迟。

### 3.4 公共 Benchmark 与真实场景分开
**公共 Benchmark：**
严格使用官方 qrels，不修改 relevance 定义，保证与 BM25/Contriever/BGE 可比。

**真实科研检索：**
先进行 Source Authenticity Gate，再对通过真实性验证的候选来源按 ResearchSpec 相关性排序。
真实任务的相关等级可以采用 0–3，但不要把这个自定义结果冒充标准 BEIR nDCG。

## 4. Stage C：多源异构整合正确性

赛事真正关心的“字段对齐、多源整合、同一对象判断、冲突处理”不能只靠最终案例展示，必须量化。

### 4.1 Schema Matching

#### 数据
Valentine Schema Matching Benchmark / Experiment Suite。

#### Baseline
- JaccardDistanceMatcher：简单可解释基线
- COMA
- Cupid
- Our Agent Schema Matcher

#### 指标
设标准字段对应集合为 G，系统输出为 P：

Schema Precision = |G∩P|/|P|

Schema Recall = |G∩P|/|G|

Schema F1 = 2PR/(P+R)

回答：
> 不同来源里“同一个含义”的字段有没有对齐正确？

### 4.2 Entity Matching

#### 数据
ER-Magellan / DeepMatcher Benchmark，建议：
- DBLP-ACM（学术数据，最贴近科学数据）
- Walmart-Amazon（结构差异较明显，作为压力测试）
可选 Dirty DBLP-ACM。

#### Baseline
- 简单规则/Fuzzy Matching
- DeepMatcher
- Ditto
- Our Agent Entity Matcher

#### 指标
Entity Matching Precision / Recall / F1。

回答：
> 两个来源中的两条记录是否指向同一个真实对象？

### 4.3 汇总显示
报告中分开显示 Schema F1 与 Entity F1。
若需要一张总览卡，可定义：

Integration Macro-F1 = (Schema F1 + Entity F1)/2

**注意：该汇总值仅用于本项目可视化，不作为外部标准指标。**

## 5. Stage D：Task-Adaptive Fitness-for-Purpose

### 5.1 为什么不能使用固定科研适用性指标
不同研究设计的数据要求不同：
- 生存分析需要 time/event/censoring/follow-up；
- 治疗响应分析需要 treatment/response/baseline/patient linkage；
- 描述性研究关注 population coverage、missingness、representation；
- 分子关联研究强调 exposure/outcome 是否在同一分析单位可关联。

因此不能用同一个固定字段列表评价所有科研任务。

### 5.2 核心方法
Evaluation Agent 执行：

Research Question
→ 识别研究设计
→ 生成 Evaluation Contract
→ Freeze
→ Research Agent 查找/解析/整合
→ 按冻结 Contract 评价

必须“先出考纲，再考试”，禁止在看到结果以后降低要求。

### 5.3 一级评价空间固定
所有任务固定四个一级维度：

1. **Research Relevance**
   - 人群、暴露/变量、结局、时间、粒度是否匹配研究问题。

2. **Analytical Adequacy**
   - 数据规模、缺失、结局变异、分析单位关联、时间逻辑、截断/泄漏等是否支持目标分析。

3. **Traceability & Reliability**
   - 最终关键事实能否追溯至真实原始来源；来源、版本、处理过程是否清楚；关键冲突是否解决。

4. **Reusability**
   - Schema/字段字典、单位、机器可读格式、原始值保留、Python/R 可继续使用、复现信息是否完备。

二级 rubric 由 Agent 根据研究类型选择或生成，但必须限制在预定义 rubric library 中，并在运行任务前冻结。

### 5.4 评分
每个二级项采用 0–4 分：
- 4：完全满足
- 3：基本满足，有轻微限制
- 2：部分满足，需要明显补充
- 1：仅有限辅助价值
- 0：不能支持该项要求

先计算四个一级维度归一化得分 r,a,t,u ∈ [0,1]。

任务适用性：
Fitness = 100 × (r·a·t·u)^(1/4)

若关键 Quality Gate 未通过，则不自动发布 Fitness，输出 REVIEW/REJECT。

### 5.5 横向比较
准备 N 个固定、真实、paper-grounded 科研任务。
每个任务先生成并冻结同一 Evaluation Contract，然后以下系统全部跑同一任务：

- Rule/Keyword Baseline
- Qwen-only
- Single-source Agent
- Multi-source Agent without Quality Gate
- Full Agent

最终报告：
- Mean Fitness Score
- Median Fitness Score
- Win Rate
- Gate Pass Rate
- 95% bootstrap CI（有条件时）

这使“二级规则任务自适应”与“系统横向比较公平”同时成立。

## 6. Quality Gate

Quality Gate 不做成漂亮但模糊的综合分，而是做科研数据准入机制：

### Gate 1 Source Authenticity
必须存在真实可验证的 accession/DOI/PMID/官方 ID/官方 URL。

### Gate 2 Integration Integrity
字段匹配、实体关联不能违反冻结 Schema 和医学/领域硬规则；不能无证据跨库拼接患者。

### Gate 3 Traceability
关键非空事实必须具备 source_id + 原始证据位置/原始值/转换链。

### Gate 4 Conflict
关键未解决冲突 > 0 → REVIEW 或 REJECT。

### Gate 5 Task-critical Requirements
Evaluation Contract 中的硬必需条件缺失 → 不允许宣称 analysis-ready。

输出：
- PASS：可进入最终科研数据集
- REVIEW：需要仲裁/人工
- REJECT：禁止纳入/自动触发重新查找、解析、对齐或整合

---

## 7. 双闭环

### 质量修正闭环
来源问题 → 重新检索
解析问题 → 重新解析
Schema问题 → 重做字段匹配
Entity问题 → 重做实体关联
Evidence/来源不足 → 补充来源
仍不确定 → REVIEW

### 科研需求补全闭环
Fitness Evaluation 发现核心科研需求缺口
→ 输出 Missing Requirement
→ 回到检索
→ 补充数据
→ 重新评价

这比“评价完只给一个分数”更符合赛题的反馈修正要求。
